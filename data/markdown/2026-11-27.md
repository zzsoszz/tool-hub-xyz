⚠️ DeepSeek Harness 隐私提醒：你的对话、文件内容、第三方模型的对话，可能都在往外发
我把本机装的 DeepSeek Harness（0.2.2-rc.5）解包了。安装包里的 app.asar 自带 TypeScript 源码，我逐个读了和数据上报有关的模块，再起一个本地假服务器抓包验证。结论如下，建议用这个工具的朋友都检查一下自己的设置。
一、完整对话日志会随模型请求上传（默认开启）
只要用的是 DeepSeek 模型，每次请求都会多带一个 dsh_session_log 字段，把会话日志按增量全部上传，内容包括：
• 你发的每条消息、模型的每条回复
• system prompt
• 工具调用的结果：读过的文件内容、执行过的命令及输出
• 项目工作目录的完整本地路径
• 生成会话标题的请求也会再带一份
我抓包实测后，还确认了两件更需要注意的事：
1️⃣ 第三方模型的对话也会被带上去。
同一个会话里，先用 Claude、GPT 等第三方模型聊，再切回 DeepSeek 模型，之前第三方模型那部分的对话原文、模型名、模型回复，都会进入上传的日志。我测过，API Key 和第三方的接口地址不会上传。
2️⃣ 中转站也能收到。
如果你给 DeepSeek 适配器配了自定义地址（中转站、代理网关），这份完整日志会照样发给那个地址。代码里没有判断请求是不是发往官方 API。
👉 关闭：设置 → 通用 →「在使用官方模型 API 时上传 Session Log」。我自己的本地记录里就查到过一次已经上传成功的对话。
二、每个 DeepSeek 请求都带固定标识（关不掉）
• x-deepseek-harness-user-id：本机生成的一个固定 UUID，存在 ~/.dsh/.anonymous-user-id
• x-deepseek-harness-session-id：会话 ID
• dsh_plugin_packages：你装的全部插件的包名和版本，第三方插件也算在内。默认开启，我在设置里没找到开关。
三、桌面版产品埋点（默认开启，界面上没有开关）
数据发往 dsh-otel-collector.deepseeksvc.com，内容有：
• 发消息、切换模型、切换思考强度、压缩上下文、分支会话、安装或卸载插件等操作
• 你用的模型名，第三方模型也会上报（比如你接了某个中转站上的 Claude，模型名也会报上去）
• CPU 型号、核数、内存大小、系统版本号（通过 PowerShell 读注册表和 WMI 获取）
• 登录 DeepSeek 账号后，还会带上 user_id 和 device_id

Hi HN, I made a small macOS utility for my own iOS simulator workflow. I kept running into two annoyances: getting config files in and out of a simulator is clunky (digging into CoreSimulator UUID folders or running simctl), and on the iPhone Duo simulator I couldn't even drag and drop images onto the window at all. SimDrop puts every running iOS simulator in Finder's sidebar (under Locations) with two folders: - Downloads/ (Files app > On My iPhone > Downloads)
- Photos and Videos/ (the simulator's Photos library) Simulators appear when they boot and disappear when they shut down. Everything is also reachable from the terminal under ~/Library/CloudStorage/SimDrop-SimDrop/. A couple of caveats up front:
- Dragging moves files by default (same as iCloud Drive, because it uses File Provider on the startup volume)—hold Option to copy.
- macOS 15+ and iOS simulators only (not physical devices). It's free, open source (GPL-3.0), signed and notarized, and installable via Homebrew: brew install --cask rxliuli/tap/sim-drop
Just sharing in case others run into the same friction—feedback or PRs welcome!

哪些设备需要查？
NFS 是一种网络文件共享协议。比如一台 Linux 主机把目录共享出来，另一台电脑把它挂载成文件夹，前者就是 NFS 服务端。这次出问题的是 Linux 内核里的 NFS 服务端 nfsd ，涉及 NFSv4.1 和 NFSv4.2 。只挂载别人共享目录的 Linux 客户端，不会因此暴露这个漏洞。

怎么处理？
用不到 NFS，就关掉。 在 NAS 控制面板关闭 NFS，或者停用 Linux 的 NFS 服务。已经挂载这些共享的设备会失去访问，需要先确认谁在用。
